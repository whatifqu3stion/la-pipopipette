# Product Requirements Document (PRD)
## 3D Dots & Boxes – Gravity Variant

## 1. Overview
A two-player, same-device, turn-based strategy game inspired by Dots & Boxes, extended into 3D with gravity constraints.

Players take turns placing edges to complete faces and cubes. Cubes award points and extra turns. Designed for web (mobile-first), later portable to mobile.

---

## 2. Grid Coordinate System
- Points: integer coordinates (x, y, z), where x,y,z ∈ {0,1,2}
- Edges:
  {
    start: (x, y, z),
    direction: 'x' | 'y' | 'z'
  }
- Faces:
  {
    origin: (x, y, z),
    normal: 'x' | 'y' | 'z'
  }
- Cubes:
  {
    origin: (x, y, z) where x,y,z ∈ {0,1}
  }

Total:
- Points: 27
- Edges: 54 (18 per axis)
- Faces: 36
- Cubes: 8

---

## 3. Core Rules
Turn flow:
1. Player taps edge
2. Validate move
3. Place edge
4. Check faces
5. Check cubes
6. Score cubes (+1 each)
7. If cube completed → same player
8. Else → switch player

Face complete: all 4 edges placed  
Cube complete: all 6 faces complete  
Owner = player who completes final element

Game ends when all cubes complete. Highest score wins.

---

## 4. Gravity Rule
An edge is valid if:
- It is on bottom layer (y = 0), OR
- There exists a completed cube directly beneath it

Simplified implementation:
- Only cubes provide support
- Faces do not provide support

---

## 5. Input Model
- Tap edge → immediate placement
- No confirm step
- Undo available (single step before next move)

Hit detection:
- Invisible enlarged edge hit zones
- Raycast selects nearest valid edge

---

## 6. Camera
- PerspectiveCamera
- Fixed isometric view
- Rotations: 0°, 90°, 180°, 270° (Y-axis)
- Target: (1,1,1)

Rotation:
- ~300ms animation
- 2–4° overshoot, single settle
- Input disabled during rotation

---

## 7. Rendering
- Three.js
- EffectComposer:
  - subtle bloom
  - light film grain

Materials:
- Edges: player-colored lines
- Faces: translucent planes
- Cubes: filled volumes

Transparency:
- depthWrite = false
- controlled renderOrder

---

## 8. Visual Style
- Minimal geometry
- Ink-like player colors:
  - Player A: #3A6EA5
  - Player B: #C75C5C
- Subtle grain (post-process only)
- Lighting-driven depth

---

## 9. Animation Timing
- Edge: 120ms
- Face: 200ms
- Cube: 300ms
- Camera: 300ms + 100ms settle

Hierarchy:
Edge < Face < Cube

## 10. Audio

- Cube: low “thunk”

Optional pitch variation

## 11. UI

## 12. State Management
Core:
- edges
- faces
- cubes
- player scores
- current player

Derived:
- valid edges
- completions

All moves processed atomically per turn

## 13. Undo
- One-step undo
- Reverts full last move
- Disabled after next move

---

## 14. Reset
- Clears board
- Resets scores
- Randomizes starting player
- Resets camera

## 17. Success Criteria
- Rules understood in <1 minute
- No input frustration
- Cube completion satisfying

## 19. Performance and Loading Requirements

### Load Time
- Game must be playable within 2 seconds on a typical broadband connection
- No blocking loading screens
- Render canvas should appear immediately

### Bundle Size
- Keep total JS bundle under ~500KB where practical, excluding core Three.js delivery choices
- Avoid large dependencies

### Rendering Performance
- Target: stable 60 FPS on mid-range laptops and mobile devices
- Minimum acceptable: 30 FPS

### Scene Complexity Constraints
- Total objects in scene should remain minimal:
  - Points: 27
  - Edges: 54
  - Faces: 36
  - Cubes: 8
- Reuse geometries and materials wherever possible

### Graphics Constraints
- No heavy shaders or expensive effects
- Post-processing must be minimal
- Avoid real-time reflections, ray tracing, physics engines, or GPU-intensive visual effects

### Initialization Strategy
- All geometry and state should be generated synchronously on load
- No async asset loading required
- No external assets required for MVP (no textures, no models, no font downloads)

### Browser Compatibility
- Must work on:
  - Chrome (latest)
  - Safari (latest)
  - Firefox (latest)
  - Mobile Safari (iOS)
  - Chrome on Android

### Graceful Degradation
- If post-processing is unavailable or slow:
  - disable effects automatically
  - maintain full gameplay functionality

### Implementation Guidance
- Prioritize responsiveness over visual fidelity
- If a visual effect negatively impacts responsiveness or clarity, remove it
- Reuse shared geometry and materials wherever possible
- Minimize draw calls
